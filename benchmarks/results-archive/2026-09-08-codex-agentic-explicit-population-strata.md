**All four strict-arm losses are hand assembly over correct tool output, and they trace to one missing query.** Recomputing from the frozen index confirms the tool's data in every failing cell: the run's own `rdeps` output gives the terra count task 19 production and 57 test importers against the answered 56, and ranking the sol task's 70 importers by their own in-degree reproduces the oracle's top five exactly, including the module the arm dropped. Each task asks the same shape — rank or count *within this candidate set* — and Codemap 0.35.0 as measured could not express it: `central` ranked the whole repository and `rdeps` returned one module's importers as names with no count. So the arm either issued one `rdeps` per candidate and counted the lists by eye (20 and 9 calls in the two counting tasks) or filtered a repository-wide ranking against its candidate list by hand. Both failures of the second kind dropped or added exactly one row; the module the sol task lost sits at global rank 69 in that ranking, above the rank-103 and rank-116 rows the arm kept, so it is a scanning slip and not a truncation. The control never reaches that step: with no tool it derives each candidate's count as it enumerates, so its working set is already scoped. `query central --among <modules>` and the `importer_count` / `excluded_test_importer_count` fields were added after this run to close the gap — they are not in any measured artifact here, and testing whether they change the result needs a new revision and a fresh paid approval.
