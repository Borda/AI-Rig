# Codex User Questions

Read once; reuse unchanged.

1. The root owns user questions. Children return context, question, choices, custom syntax and answer mapping; never open controls or print a user-facing fallback.
2. Reuse unambiguous answers. Otherwise freeze scope and map labels/aliases to canonical values; one pending decision per workflow. Bind through host identity or an unambiguous conversational answer for the sole unchanged decision; ambiguous binding requires a visible key.
3. Inspect schemas/restrictions; discover deferred `ask_user` with tool search or `functions.exec` `ALL_TOOLS` before async. Prefer permitted synchronous `request_user_input` when choices fit, otherwise invoke native form. Async needs verified usable control; unknown means unsuitable. Printing payload is not asking. Tool acceptance does not prove a selectable form was rendered.
4. Show context once, without duplicating the question or choices. Closed choices use distinct actionable options, with an evidence-backed `(Recommended)` choice first. Open-ended syntax needs free text and complete grammar in the control; `ask_user` omits options for this case. Preserve every required action. Never invent an `Other`/`Custom` button or force two presets.
5. Explain approval and denial effects; use `Approve`/`Deny` or exact action labels. A preapproval brief is context, not a question: missing workflow consent uses the native control; existing consent skips reconfirmation. Runtime permission requests use the dedicated runtime mechanism, not question tools.
6. Record answers against frozen scope; verify `ask_user` decision ID and scope digest before consuming an answered receipt. Unsupported, cancelled or declined forms grant no consent. Required work stays pending. Tool acceptance, silence, preselection, examples and unrelated text grant no consent. Idle after accepted async: yield without final/status, including empty final. Accept clear Approve/Deny for one unchanged pending decision; supersession and exact-token/digest rules still apply. Optional defaults require permission, response opportunity and stated assumption. Never replay completed decisions.
7. Use plain text when no form works or the host requires it; explain why. Dismissal makes that control unsuitable; see details. Async text stays pending for typed reply. No widget probes or settings changes.

For exact-token/digest confirmation, uncertain binding, changed scope, delayed answers, resumption, control failure, or text/headless fallback, read [detailed rules](codex-user-questions-details.md). Keep decisions pending while resolving uncertainty.
