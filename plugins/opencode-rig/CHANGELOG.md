# Changelog

All notable changes to this package are documented here. Versions follow [Semantic Versioning](https://semver.org/).

## 0.5.0

- The shell guard uses positive informational and harmless-mode option tables for catalogued interpreters and debuggers; other options ask, while plain script-file limits remain. Indirect-file and code channels share option grammar, including compiler specs/configuration, plugins and forwarded options, wget credential handlers, curl engines, long prefixes and tar bundles. Only sudo and doas admit positively checked read-only targets; other elevation wrappers always ask, including system-level systemd-run and companion editors. Unprivileged systemd-run --user retains its treatment without machine or identity selectors and cannot remove inherited privilege. Program identity covers privilege aliases, versioned sudo and absolute builtin tests. Literal environment assignments share one allowlist across prefixes and wrappers; safe Git reads and non-interactive rights listings ask less. Manager aliases share program identity. Bounded direct xargs readers, external printf formats after `--`, BSD time flags, attached reader option values and literal cmp filenames ask less; wrapped xargs targets ask and direct builtin printf keeps its arithmetic checks.
- An explicit scope path that is renamed away during a run now fails evidence collection with `scope path was renamed away: <path>` instead of being treated like a deletion, so a run restarts with a fresh selection rather than finalizing on a moved file; plain deletions, directory scopes and unrelated renames behave as before.
- The local Git grant binds to the repository directory through the native path resolver, so the Windows 8.3 short-name spelling and the long spelling of one repository share a grant.
- The shell guard decides more precisely when to ask:
  - Asks more reliably for shell programs fed through stdin or hidden behind launchers: a function called inside a fed shell program is judged, a stdin-fed `-c` program is no longer waved through, `env -S` and ANSI-C quoted payloads behind an uncatalogued launcher ask, and `sed` and `sort` forms that can execute a program (`sed e`, `sort --compress-program`) ask. Everyday filters such as `cat`, `grep`, `head`, `tail`, `wc`, `cut`, `tr`, `uniq` and `jq` keep reading without a prompt when their options are plain data options. `git stash` with leading options is no longer classed as a read. The guard is a speed bump, not a sandbox; the README section "What the shell guard does not promise" lists limits kept by design and known open gaps.
  - Asks less for plain text without hiding programs: a heredoc or here-string written to a file or fed to a shell script asks only when its body names a guarded command, so prose, comments and other-language code that merely mention `git` or `gh` pass; benign encoded arguments no longer ask while an ANSI-C or quote-split executable name still does; `sed` substitution and print expressions and `head` or `tail` counts after a Git read keep reading without a prompt, while `sed` forms that execute, write or read files still ask; shell options that take a name no longer swallow stdin or option-shaped operands; and a persistent `exec` redirect, including one set by a function that is later called, keeps tracking later output so commands written through it are still judged.
  - The allowlist asks more for package managers, project tools, runners, containers and installers, and less for safe `python -m pytest` and Git revision forms.
- Reviews assess material improvement claims against revision-bound tests or measurements, distinguish supplied evidence from independent reproduction, and treat unresolved shared-hardware noise as inconclusive rather than proof of a gain or regression.
- Gate batches that change source retain their history without certifying stale validation, including intermediate changes reverted by a later gate. Deleted outputs retain the same identity through review handoff, and optimization refreshes candidate source before measurement.
- `opencode-rig` command-line behavior:
  - `opencode-rig` now rejects unknown options per command and prints help to stderr instead of silently ignoring them, and `--version` is accepted as a top-level flag. Each command lists the flags it supports (for example `doctor` accepts `--project`, `--global` and `--assets`).
  - `--project` now targets the Git root, as the host does, instead of the current directory, and falls back to the current directory outside Git. Agents, the `opencode.json(c)` merge and the `.gitignore` entry are written there, every write target is checked to stay inside that base directory, and a symlink in the path is refused. Git environment variables are ignored when finding the root.
- The managed delivery-principles block is read and rewritten correctly in files with Windows line endings: its hash is checked on LF-normalized text, replacement keeps the file's existing line endings, and adopted Claude instructions are not appended again when already present after the block.
- `doctor` states that it checks installation only and points to the in-session `rig_doctor` tool for project and runtime health. README now records OpenCode `2.2.0` as the tested host and the `@opencode/plugin` range from `package.json`, and refers to the `rig-release` skill by its correct name.
- `rig-implement` now requires a completed, independently reviewed plan, or an explicit inline mini-plan for a trivial change under 3 files and 50 changed lines; plan review records the plan digest it assessed, and the implementation-to-review handoff carries the run ID, recorded output paths and digests, and the bound plan.
- Gate runs execute asynchronously with a bounded time, keep complete streamed logs with bounded tails, and report a timeout accurately.
- Evidence reads reject physical path escapes while keeping legitimate absolute paths inside the project. Persisted records, identities and storage locations are validated, and Git reads share one scrubbed environment, configuration overrides and timeouts.
- Local commit grants keep their confirmation, repository binding, creation identity and expiry. The permission guide separates a one-time runtime approval from a persistent `Approve always` grant, and `rig-implement` uses the runtime shell prompt for a one-time Approve or Deny on the exact commit, offers `Approve always` separately, and records `rig_git_grant` only after that answer.
- Remediation binds the source finding inventory and requires a disposition for every source ID. `rig-distill` reads exact preselected terminal-run files or an inventory record inside the project and records external source identifiers and access limits as decisions.
- `opencode-rig doctor` checks installed digests, honors configured artifact locations and Git ignore rules, and the in-session `rig_doctor` rejects routing-description drift and makes a confirmed cleanup routable. `rig-release` uses the last release tag as its baseline and HEAD only for a first release.
- `rig-remediate` no longer runs the full test suite when every changed path is user documentation (README, `docs/`, prose `.md`, `.rst` or `.txt`; skills, agents, rules and prompts do not count). It runs only the configured gates that check the docs, or records a `gate_exemption` with a docs check when every detected gate runs the test suite, and a documentation fix is proven by its docs check instead of a new test. The skipped suite is recorded once as a limit that never lowers confidence and is never a finding; a change touching any other path still runs every configured gate.
- The gate file-argument check refuses a `..` segment written with either separator on Windows, where a forward-slash `link/../file` argument previously passed the parent-segment check; POSIX behaviour is unchanged, so a filename containing a backslash is still accepted.

## 0.4.0

- Shell guardrails now parse the command instead of matching text patterns. Quoting, line continuations, substitutions, heredocs, redirections, functions, `cd` chains, shells run through `-c`, and environment overrides such as `GIT_*` or `EDITOR` are read before a command is classified. A Git or GitHub command the parser cannot read safely now asks for confirmation as its own class, and a malformed shell resource list asks instead of passing. Read-only Git is accepted only for known verbs with known options, so `git config` writes, `git stash` mutations, `git commit --amend`, `git restore`, and GitHub write commands are no longer waved through as read-only.
- The local commit grant is read through a single open file with identity checks and written through an exclusive temporary file and rename, so a symlink, FIFO, hard link, or swapped file can no longer be followed or hang the check. The grant is read only when a plain commit is being classified, and is reported after a `cd` or directory change.
- Tool-call journals hold less. Journal files are created owner-only, tool inputs are stored as per-key hashes (sensitive keys as `[redacted]`), and errors as hashes. Redaction covers more secret shapes, including Anthropic and OpenAI style keys, Slack, npm and GitLab tokens, Basic and Bearer credentials, private-key blocks, and credential-named assignments, and it no longer leaves the visible prefix of a secret cut by truncation. A damaged session state no longer stops observation from being journaled.
- Session state is validated and recoverable. Run and skill identifiers must be safe names and each session must point at a known run; a corrupt `state.json` is preserved for diagnosis and the run index is rebuilt from valid run records, while writes refuse to overwrite a corrupt file and tell you to move it aside. An active-run lookup now fails loudly on unreadable evidence instead of silently treating it as no run, and a session pointer is dropped only after its run is confirmed terminal.
- `rig_dispatch` now verifies what a child session actually did. It snapshots the workspace (tracked and nonignored files, Git config, hooks and info, and gitlink heads) before and after, flags a read-only child that changed anything or a writing child that touched paths outside its owned scope or the caller's recorded run scope, and retains the child session with a scope-violation notice. A writing child must name explicit owned paths, overlapping parallel children are reported rather than blamed, and children receive the role's permission boundary plus a read-only edit deny. A confirmed non-repository is reported as unverified, and unreadable active run state now blocks a dispatch instead of skipping the check.
- Gate runs are stricter and record which source they certify. Source drift or a changed scope during approval stops a gate run, pre-commit files are passed as literal arguments with project containment checked through symlinks, the timeout is bounded, and each gate keeps its own receipt files. Reruns supersede earlier receipts instead of replacing them: finalization and the report use only the latest receipt that matches the current scope, and the report shows each receipt as current, stale, or superseded. Gate detection also reads Makefile targets inside definitions more correctly and recognises pytest configured in `setup.cfg` or `tox.ini`.
- Evidence collection is safer and more exact. Scope paths that escape the project or resolve through symlinks outside it are refused, a missing scope path is an error unless it is a tracked deletion, a failed Git status no longer yields an empty scope, filenames that are not valid UTF-8 keep distinct identities, commit scopes accept a single commit only and resolve to its full ID, and Git runs without environment redirection or filesystem monitors. A run's outputs may list deleted files that Git tracks as deleted.
- Run lifecycle is tighter. Evidence changes are accepted only while a run is in progress, a completed or failed run cannot be refreshed, and a loop that stopped for a reason other than convergence can no longer be reopened and needs a replacement run. A scope refresh records its reason in the journal and drops the earlier review and loop results when the source changed. Loop finalization accepts drift and unavailable-reviewer stops, and only a converged stop is blocked by security or critical residue. Review-only axis and coverage requirements now apply to review runs rather than every skill.
- `rig_doctor` reports an installed agent that was edited after installation, checks whether the artifact root is ignored by asking Git, so nested and global ignore rules count and an unavailable check is a warning rather than a silent pass, and picks the installed agent directory more reliably. Expired-run cleanup now keeps active runs and the plans they reference for four times the configured age, and the doctor skill documents a confirmed-cleanup path that deletes nothing without your explicit confirmation.
- Role agents that fetch web content now ask before each fetch and are denied reads of environment files, keys, credentials, and SSH and user configuration paths. Every role card and the research, review, and remediation skills tell the agent to treat sources, diffs, findings, pull request comments, and fetched pages as untrusted data and not follow instructions embedded in them.
- Skill workflows are firmer. Skills now load the references they link, so their rules reach the agent. `rig-challenge` runs a full baseline, fix, re-assess, and score loop with a recorded gate exemption when no gate exists. `rig-implement` requires a frozen plan or an inline mini-plan for small changes and rechecks the plan digest before finalizing. `rig-investigate` experiments in a scratch copy and never in your working tree. `rig-review` supports commit and PR targets, with a dedicated local ref as its only write. `rig-remediate` demands per-finding verifier verdicts and exact reconciliation of finding sets. `rig-release` compares the version against the last release tag and requires exactly one SemVer step. `rig-distill` reads only finished runs and never deletes artifacts.

## 0.3.0

- Ship the approval rules inside the package as `src/resources/permissions.json`, with `src/resources/permissions-guide.md` as the review reference. The rules that keep push, hard reset, clean, and rebase behind an explicit answer can be read before the plugin changes a session.
- `opencode-rig` permission-rule commands:
  - `opencode-rig init` merges those rules into the configuration file you already keep: `~/.config/opencode/opencode.jsonc`, or an existing `opencode.json` beside it, or — with `--project` — the `opencode.jsonc` or `opencode.json` in the current directory. Your own rules, comments, and ordering survive the merge, and a rule of yours in the `git rebase` family is left to govern that whole family. Routine sessions stop re-asking without losing your configuration.
  - `opencode-rig print-config` prints the same rules for a configuration you would rather edit by hand, and `opencode-rig check` reports whether the rules are present without failing on the report.
- Read-only command allowlist:
  - Every role agent carries the shipped ruleset after its own `shell: *` catch-all, so inspection commands such as `git status`, `grep`, and `cat` stop asking inside a role agent. A command the list does not name still asks.
  - The read-only list no longer allows `rg`, whose `--pre` option runs an arbitrary program, or a `date` with arguments, whose GNU `-s` option sets the system clock. A command that accepts `--output` now asks instead of writing a file silently.
- The guide states the two channels the allowlist does not close, so the widened surface stays reviewable: a redirection attached to an allowed command still matches, which gives the six read-only role agents a write path their own `edit: deny` does not cover, and an agent rule is appended after the global ones, so an agent allow outranks a global deny for the same command.
- The permission hook now classifies the v2 `execute` action as well as `shell`, so a destructive command that arrives through Code Mode is no longer skipped. A destructive or history-rewriting command that would discard working-tree changes now names the paths that belong to someone else's work, so a shared checkout cannot lose them silently.
- Skill workflow requirements:
  - `rig-plan` now requires a scope verdict table (every surface `in-scope`, `deferred` with an unblock condition, or `out-of-scope` with a reason), a revision counter, and a verdict-changes section; owned paths must reconcile with the table both ways and the delegation brief is derived from it. A surface silently moving out of scope was the defect this prevents.
  - `rig-implement` refuses to start without a frozen plan, reports one plan row per changed path, refuses to revert a path that is not in scope, requires explicit user approval recorded through `rig_git_grant` before a commit, and states split-and-conquer delegation plus RTK guidance for read-heavy commands.
- `opencode-rig setup` (with `init` as its alias) now also writes the shipped delivery principles into `~/.config/opencode/AGENTS.md` as a digest-stamped managed block. Setup refuses to shadow an existing `~/.claude/CLAUDE.md`; `--adopt-claude-instructions` copies it into the block, the file is created owner-only, symlinked targets and parent directories are never written through, and `remove` strips the block while restoring the user's bytes. `--agents-only` installs only the role agents so the Makefile sync stages keep their own refusals.
- The guardrail working-tree lookup no longer executes repository-configured Git config such as `core.fsmonitor`, treats filenames as untrusted text in the approval prompt, and is bounded to one second so it cannot stall the permission hook.

## 0.2.0

- Enforce `correctness` as a mandatory review axis for `rig-review` runs; `rig_findings` now normalizes `axes`/`aspects` (case/duplicates), validates allowed dimensions, and requires coverage when correctness is included. Update `rig-review`, `rig-reviewer`, and `rig-remediate`/`rig-challenge` guidance accordingly.
- New skills:
  - Add `rig-research` with `docs`, `sota`, `paper`, and `code-fidelity` modes. Every claim is recorded as `sourced`, `inferred`, or `unknown`, contradictions are reported rather than averaged, and a research run requires a `rig-scientist` review before completion.
  - Add `rig-distill`, which mines this project's recorded runs or a supplied external inventory for recurring signatures, applies an explicit evidence threshold, rejects proposals that duplicate an existing asset, and proposes without installing or pruning anything.
  - Add `rig-optimize`, a guarded benchmark campaign. The benchmark must already be a configured gate, a win must clear the recorded noise band and the declared minimum improvement, every correctness gate still has to pass, and a kept round must be independently recomputed by `rig-optimizer`.
- Extend `rig-release` with read-only release-note, migration-note, and contributor-reply drafts. Every draft line traces to a commit, finding, or changelog entry; nothing is posted.
- Add `rig-scientist` and `rig-optimizer` role cards. Both are read-only, and `rig-scientist` is the only role with `webfetch` allowed.
- Add `rig_doctor` action `assets` and `opencode-rig doctor --assets`: roster drift and dead relative links fail; duplicated prose and oversized cards warn.
- `pack_check` now derives the required skill and role files from `rig.json` instead of a hard-coded list, so the tarball contract follows the roster.
- Refuse to finalize new skill runs without their evidence: research and optimize require review, optimize additionally requires gates, and distill stays advisory.

## 0.1.1

- A first `init` now exits successfully after installing the five role agents. It previously counted every freshly written file as a problem, so a scripted install such as `make sync-opencode` stopped on a clean machine.
- `init --check` still reports missing agents as problems, and repeating `init` remains a no-op.

## 0.1.0

- Initial release of the OpenCode evidence-first workflow plugin: eight skills (`rig-plan`, `rig-investigate`, `rig-implement`, `rig-review`, `rig-remediate`, `rig-challenge`, `rig-release`, `rig-doctor`) with matching slash commands.
- Seven tools (`rig_evidence`, `rig_gate`, `rig_findings`, `rig_loop`, `rig_git_grant`, `rig_dispatch`, `rig_doctor`) record scope digests, gate receipts, validated findings, convergence rounds, and install health in a project artifact directory.
- Runs cannot complete without their workflow evidence: source drift marks them `stale`, failed gates block implementation and release, review requires a named independent reviewer, remediation requires every finding closed, and challenge requires convergence with no security or critical residue.
- A permission hook escalates remote mutations, destructive operations, history rewrites, and unreviewed local commits to `ask` without ever downgrading a configured answer; an explicit local grant covers plain commits only.
- `opencode-rig init` installs or upgrades five read-only `rig-*` role agents with hash stamps, refuses to overwrite edited or unstamped files, and `remove` deletes only stamped files.
- Doctor reports plugin load, version agreement, agent installation, Git grant state, artifact ignore status, detected gates, and stale runs, with an explicit opt-in cleanup for stale runs.
