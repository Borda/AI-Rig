# Mode: consolidate — foundry:audit

Triggered by `/audit [<scope>...] --consolidate`. Check 47. Finds narrow instruction sections that express one intent in different words and proposes fewer, broader ones, so the agent loads and navigates less. **Advisory only**: sources are never edited, no finding enters the fix gate; the only files written are run artifacts under `.temp/` and `.reports/` and the standard skill-state files (`.temp/state/preflight`, `.temp/state/skill-contract.md`), which are replaced or removed by name and never written through a link. Standalone: `audit_preflight.py` rejects it combined with `--upgrade`, `--adversarial` or `--efficiency`.

Owners (do not duplicate): verbatim/near-verbatim pairs → Checks 18c/33; single-file restatement → Check 29 and efficiency E8; agent-vs-agent roster overlap → Checks 20/46. This mode takes cross-file intent overlap inside one load group; a section covered by those owners is listed there, not re-reported here.

```text
CONSOLIDATE_MIN_GROUP_TOKENS=1500    # unblocked tokens a group needs before it is worth examining
CONSOLIDATE_MAX_GROUPS=12            # groups examined per run; truncation always reported
CONSOLIDATE_MIN_CLUSTER_TOKENS=400   # a smaller cluster cannot repay a judge; listed, not judged. A mergeable one must also hold half this beyond its largest member
CONSOLIDATE_MAX_JUDGED=20            # clusters judged per run, mergeable first then largest; the rest listed with the reason
CONSOLIDATE_JUDGE_BATCH=5            # clusters per judgment agent
CONSOLIDATE_REVIEW_BATCH=5           # proposals or edits per review agent
```

`--fast` only widens fan-out (`--batches 5`, the `CAP_OPUS` ceiling, instead of `MAX_BATCHES`); it never changes which groups are examined.

## Boundary — enforced

- Pre-flight prints `dispatch=mode:consolidate`; the skill then runs this mode and no other step: not Step 1 (`pre-commit --all-files` rewrites sources), not Steps 1b–11, not the follow-up gate.
- Sources are never written. Writes: `$RUN_DIR/consolidate/`, the `consolidate-run-dir` sentinel, and the compaction contract (cleared in Phase 6).
- Never writes `audit-state-${CSID}/run-dir` (that arms the fix-gate hooks) and never writes `summary.jsonl`.
- Needs the plugin source tree: no `plugins/` dir → `! BLOCKED — --consolidate needs the plugin source tree; run it with --local in the checkout`.
- Every spawn follows `_shared/agent-spawn-protocol.md` §Deadlines: Write `$RUN_DIR/consolidate/agent-watch-<wave>.tsv` (`<name>\t<out file>\t900`) in the spawn response, end the turn, run `agent_watch.py --state-dir "$RUN_DIR/consolidate"` once per notification. Missed deadline → ⏱ `timed_out`, record, continue; never wait. Spawn names `cluster-N`, `judge-N`, `review-N`.

## Phase 1 — Inventory (zero LLM)

```bash
export CSID="${CLAUDE_CODE_SESSION_ID:-$PPID}"
[ -d plugins ] || { echo "! BLOCKED — --consolidate needs the plugin source tree; run it with --local in the checkout"; exit 1; }
RUN_DIR=$(python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/make_run_dir.py" .reports/audit)  # timeout: 5000
[ -z "$RUN_DIR" ] && { printf "! BREAKING: make_run_dir.py returned empty path\n"; exit 1; }
mkdir -p "$RUN_DIR/consolidate/proposals" "${TMPDIR:-/tmp}/audit-state-${CSID}"
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" stash --root . --path "${TMPDIR:-/tmp}/audit-state-${CSID}/consolidate-run-dir" --text "$RUN_DIR"  # timeout: 5000 — replaces the file by name, never writes through a link
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" inventory --root . --out "$RUN_DIR/consolidate/inventory.json"  # timeout: 60000
echo "RUN_DIR=$RUN_DIR"
```

Skill files are found by directory: the default `skills/` of every Claude plugin plus the directories its manifest adds (`skills` as a `./` path or a list of them, such as `./claude-skills/`; a folder holding `SKILL.md` directly is one skill with its fragments, and with `.` registered each child folder holding `SKILL.md` brings its own (the file makes the folder a skill, whatever the folder is called), a skill kept at the plugin root brings the Markdown beside it except `CLAUDE.md`, docs and the folders of other components; `.` names the `SKILL.md` at the root and the `SKILL.md` files one level down, both when both exist; a path leaving the plugin is ignored), the command files (a command is loaded when invoked, as a skill is, and is covered with the skills in one lazy group: every Markdown under `commands/`, or what a manifest `commands` path, list or `source` map names, which replaces the folder; inline `content` has no file), and the agent files of every Claude plugin (every Markdown under `agents/`, subfolders included; a manifest `agents` list replaces the folder), every Markdown under a skill except its `ARCH.md`, `README.md` and `CHANGELOG.md`, which are listed under `excluded`). `inventory.json` also records `digests`, the sha256 of every file it examined (this mode file included when run from the checkout), and `citation_digest`, one hash over every Markdown file under `plugins/` because any of them can cite a section, and `shared_digest`, one hash over the shared-file membership (which files are byte-identical copies, so which may not be merged): every later step rebuilds the inventory from the tree (same root and kinds) and compares the two documents whole, stopping when any part differs (a source, this mode file, a citing document, an added or removed instruction file, the shared-file manifest, or a hand-edited item, group or flag), so a run is never reported against text it did not examine and no derived fact is trusted; re-run `inventory` to start over.

Item fields the later phases rely on: `id`, `file`, `start_line`/`end_line`, `tokens`, `load` (hierarchy, paths, owner, side, pair), `group`, `inbound` (files citing the section as `<file> §<Heading>`), `blocked`. `group` is the **merge scope**: sections merge only inside one group. Always-loaded rules form one group per plugin, except `CLAUDE.src.md` (copied and user-edited, so its own group) and a rule that also ships a `-delta` variant (delivered one or the other, so each its own group). Scoped rules group by exact `paths:` globs, read from a block list, a flow list or one scalar; any other YAML spelling (folded or literal scalar, anchor, tag, duplicate key, or a `paths` key that is indented or inside a flow mapping) leaves the rule in a group of its own, so it is never merged. Lazy sections group by skill (every file the skill can load) or by the plugin's agents. `blocked` lists unresolved dependencies — shared-file copies, policy-sibling markers (resolved or not), frontmatter (routing or scope metadata); a blocked section is never clustered.

Merging is allowed only in `always` and `scoped` groups. A lazy group (skill or agents) holds files that load on different triggers, so its clusters may only be `sharpen` or `keep`: text moved from a mode file into the entrypoint would charge every other mode for it.

## Phase 2 — Select groups

Scope tokens come from the `scope=` line pre-flight printed and are a union, as in the audit skill's scope grammar: a kind (`rules`, `skills`, `agents`), `plugins` (everything), a plugin (`foundry` or `cc_foundry`), an agent file name, or a skill name each add the groups they name. No token = everything. A token that names nothing stops the run before any spend (`! BLOCKED`, exit 1). Substitute `SCOPE` with that line's tokens (an empty string when none) before running:

```bash
export CSID="${CLAUDE_CODE_SESSION_ID:-$PPID}"
IFS= read -r RUN_DIR < "${TMPDIR:-/tmp}/audit-state-${CSID}/consolidate-run-dir" 2>/dev/null || RUN_DIR=""
[ -n "$RUN_DIR" ] || { echo "! BLOCKED — consolidate run-dir sentinel missing; re-run /foundry:audit --consolidate"; exit 1; }
SCOPE='<scope tokens>'
case "$SCOPE" in *'<'*'>'*) echo "! BLOCKED — substitute SCOPE with the scope= tokens from pre-flight (empty string when none)"; exit 1;; esac
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" select --inventory "$RUN_DIR/consolidate/inventory.json" --scope "$SCOPE" --min-tokens 1500 --max-groups 12 --batches 4 --out "$RUN_DIR/consolidate/selection.json"  # timeout: 30000
```

With `--fast` run the same block with `--batches 5`. `selection.json` holds `selected`, `batches` (group ids per curator, balanced by unblocked tokens), `not_examined` (each with its reason: single-file group, below token floor, group cap) and `unmatched_tokens`. Report every `not_examined` entry and unmatched token: the run states what it did not look at. Nothing selected → `! BLOCKED — no group in scope reaches the examination floor` and stop.

A cluster with `ok: false` skips Phases 4–5 and goes to the report's "rejected by guard" table with its `reasons` (unsafe or duplicate id, fewer than two distinct members, members already claimed, one-file cluster, blocked member, mixed scope, flattened stub/`_full` pair, unknown member). A cluster with `ok: true, judge: false` is listed with its `skip_reason` (`below cluster floor`, `below saving floor` — a mergeable cluster whose members besides the largest hold under half the floor — or `judge cap`), not judged. Cross-scope merges are never proposed.

## Phase 4 — Judge (`foundry:curator`)

Only clusters with `judge: true` (`jq -r '.clusters[] | select(.judge) | .id' vetted.json`). Batches of `CONSOLIDATE_JUDGE_BATCH`, prompt from `consolidate-judge-prompt.md` loaded as in Phase 3, substituting `<RUN_DIR>`, `<CLUSTERS>` (the batch's cluster ids) and `<OUT>` (`<RUN_DIR>/consolidate/judgments-N.json`). Outputs per batch: `judgments-N.json` and one `proposals/<cluster-id>.md` per merge-prune cluster.

After the wave, settle deterministically. The script — not the judge — applies the rules:

- A merge in a lazy group, without a complete obligation map (every entry has `original`, `from`, `to`, `modal_preserved: true`; `to` appears in the proposal; every member, the survivor included, is covered), with a stray survivor, missing or not shorter than its members, or that deletes a section other files cite, or renames or drops a cited heading of the survivor (its own or a level-5/6 one), without a `repoint`, is downgraded to `sharpen` with the reason. A downgraded merge and a sharpen with no edit list are advice only: reported `unvalidated`, never sent to review, never ready to apply.
- Every sharpen edit must name a member file and a `lines` range wholly inside one of the cluster's sections and clear of every blocked section of those files, else the sharpen is `rejected`; an edit that removes a heading other files cite (the section's own or a level-5/6 one inside it; a copy inside a code fence is not a heading) needs every citing file under `repoint`, else `rejected`; in a lazy group, net text leaving some files and arriving in others (at least 20 characters) sets `crosses_files` and goes to review — whether it is a move is the reviewer's call, never a string test, and a `weakens` verdict rejects it as the merge it is; only an `add` with no replaced text skips review, and the same text added twice does not. Any other action, spelling or shape goes to review.
- A merge-prune carries no `edits`: its change is the proposal, and side effects go under `repoint`. A merge with edits is downgraded to advice, because edits beside the proposal would grow or alter text the savings and the review never count.
- Judgments correspond one-to-one with clusters marked `judge`: a duplicate, unknown or ineligible judgment is `rejected`, a missing one is `unjudged`. Each judgment is first reduced to a strict typed record (text fields, `repoint` as a list of text, edits as objects with only `file`, `lines`, `action`, `before`, `after`, obligation entries with only their four fields); a field of the wrong type (an obligation field, or `shared`, `distinct` or `proposal`, that is null or not text; `triggers` that is not an object of text) makes the whole judgment `rejected` as malformed, and nothing outside the schema is ever copied into a file or a reviewer input.
- `inventory.json` and `vetted.json` are checked for shape before use (record fields, nested types, a `schema_version` that is the plain integer 1, group ids, and a cluster id that is a safe file name; a review lacking text cluster, digest and verdict, or a `holds` without evidence text, is no verdict; `NaN`, `Infinity` and numbers too large for a double in any artifact are refused). `vetted.json` records the floor and cap it was made with, and `settle` runs `validate` again on the report's own cluster ids and member lists and refuses a report that differs in any way (locations, citing files, guarded headings, whether merging is allowed, the load class, which clusters are judged and why), so a hand-edited flag cannot change a verdict. A bad file exits 1 with the first problems found, never a crash and never a file operation outside the run directory.
- A heading is read one way everywhere (one block reader that follows CommonMark: blockquotes and list items nest and close by their own continuation rules, a paragraph line may continue lazily, a fence or HTML block ends with its container, ATX headings with up to three spaces of indent and setext headings over the paragraph above their underline count in any container at any level, never inside a code fence, an HTML block or an HTML comment, a link reference definition (a label without an unescaped bracket, a destination without space or control character, an optional title; each part may sit on a line of its own and a title may run over several lines) is no title, lines end only at a line feed, carriage return or both, and a line is blank only when it holds nothing but spaces and tabs). A merge is checked the same way: the proposal replaces the survivor's lines and the other members' lines go, so a proposal that leaves a fence or comment open and hides a cited heading outside the cluster is downgraded, and a proposal must carry as many headings of a cited title as the survivor had cited ones. Citations are read per file mention (`a.md §A, b.md §B` gives A to a.md and B to b.md, `a.md §A, §B` gives both to a.md; only a file name followed by `§` starts the next citation, so a name inside a quoted title stays in the title, and a citation that runs on into prose after the title still names it; quotes, emphasis, code ticks, HTML tags and entities and link targets and bracket pairs around a heading are dropped on both sides, link targets (nested parentheses, titles, escapes) are parsed and dropped before entities are decoded, autolinks keep their text, raw HTML tags (a quoted attribute may hold `>`) and comments are dropped, a quoted or ticked cited title may hold `;` and `|`, a heading is also guarded when the text after any `<file>.md §` or `<file>.md (§` begins with its whole title at a word boundary (so a title holding `;`, `|` or `§` is found however it is written; the cited text runs to the end of the paragraph, up to 2,000 characters or 20 times the longest heading, whichever is more, citations are read paragraph by paragraph as the CommonMark block reader sees them, with the markers of quotes and list items removed, so a list of sections or a file name and its section sign that wrap onto the next line of the paragraph are one citation in any container, while a blank line or a new block ends it; each heading is a unit of its own (one heading never runs on into the next), code and HTML are read without the markers of the quotes and list items around them, and a file name that wraps onto the next line is still found, and a file name may hold spaces), and a long prefix still counts in either direction so a citation of `Phase 4a` guards `Phase 4` (an extra guard costs one repoint, a missing one lets a cited heading vanish), backslash escapes are removed before markup so an escaped mark and a bare one reduce alike, white-space runs count as one space and case is folded on both sides, a survivor's cited headings are read again in the whole file a merge produces, so `§CI` finds `##### **CI**`, and a title may hold a balanced code span such as `§Run `tests\`\`). The parallel agents' lists are joined by `consolidate_inventory.py collect`, never by a shell redirect. Frontmatter is read only when every top-level line is a bare `key:` line; any other spelling leaves the rule unmerged, and a flow list ends at its first unquoted `]` with its comments dropped before reading, so `[a] # x]` and `['a]', 'b']` are not the same scope, and a list with a blank line inside it is left unread, the quote state runs from line to line so a `#` inside a quoted item is text, a plain scalar YAML reads as a comment, null, boolean, number or date is no glob, block-list items must all start at one indentation, an item that starts like YAML structure (`- `, `? ` or `: `) or reads as a YAML number (binary, signed hex or octal, underscored) or indicator is no glob, only space and tab are white space (a no-break space is part of a glob), and a frontmatter holding a tab, a line break YAML knows besides `\n` or a control character is left unread; so is any value PyYAML rejects (a missing or doubled comma in a flow list, `:` or `?` inside a plain flow item, a `,` or `}` that starts a scalar, a scalar or flow list at column 0, a comment ending a plain item); that covers every other frontmatter entry too, since PyYAML refuses the whole block, so a spelling the reader cannot prove valid (an anchor, a tag, a flow mapping, an unclosed quote, a colon inside a plain value, a date or a number spelling that can fail while the document loads) leaves the `paths:` beside it unreadable. The scripts write only run artifacts: `--out`, `--review-inputs`, `--proposals-dir` and the obligation files must resolve (symlinks followed) into `.temp/` or `.reports/` of the tree, or into the system temp directory outside it, and never into `plugins/`, `.claude/`, `.codex/` or any other file of the tree; after `inventory`, every later step writes only inside the directory holding that run's inventory, never into another run's; anything else is refused. Every write replaces the file by name (a fresh staging file, then an atomic rename), so a symlink or hard link already standing at that name, or a file sharing its inode, keeps its content; `consolidate_inventory.py stash` saves the run directory for later shell blocks the same way, and the pre-flight state files use the same replace-by-name write. Pre-flight refuses `.temp/state`, `.temp/state/preflight` and `.reports/audit` when any of them resolves (links followed) into the tree outside `.temp/` and `.reports/`, `write_skill_contract.py` does the same for `.temp/state`, `make_run_dir.py` refuses a base that resolves into `plugins/`, `.claude/` or `.codex/` and always makes the timestamped directory fresh (an existing one is refused, so nothing planted in it is inherited), and pre-flight also refuses a `TMPDIR` whose `audit-state-*` directory resolves into those sources, since creating, replacing or removing a state file or run directory there would reach an instruction source. Source files that resolve outside the tree (symlinks) are listed under `excluded`, not inventoried. A sharpen's removed text is read from the file's own lines, not from the judge's quote. A sharpen is checked by applying its edits to the file and re-reading the result: every heading other files cite in the touched files, members or not, must still exist, whatever the edit looks like, and two edits covering a common line are `rejected`. A review verdict is bound to a digest of the change shown plus the hash of the original files.

Pricing: it prices savings by load class (`always` = every session; `scoped` = every session touching a matching file; `lazy` = per invocation of the owning skill or agent; no invocation frequency is estimated, so lazy savings are never summed with always-loaded ones), writes `proposals/<id>.obligations.json` for each surviving merge, and writes `review-inputs.json` for everything that needs independent review: every merge-prune, and every sharpen with an edit other than a pure add. Obligation files of a merge that no longer stands are removed.

```bash
export CSID="${CLAUDE_CODE_SESSION_ID:-$PPID}"
IFS= read -r RUN_DIR < "${TMPDIR:-/tmp}/audit-state-${CSID}/consolidate-run-dir" 2>/dev/null || RUN_DIR=""
[ -n "$RUN_DIR" ] || { echo "! BLOCKED — consolidate run-dir sentinel missing; re-run /foundry:audit --consolidate"; exit 1; }
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" collect --dir "$RUN_DIR/consolidate" --glob 'judgments-*.json' --out "$RUN_DIR/consolidate/judgments.json"  # timeout: 10000 — no match (every judge timed out) gives []; settle then records the clusters as unjudged
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" settle --inventory "$RUN_DIR/consolidate/inventory.json" --vetted "$RUN_DIR/consolidate/vetted.json" --judgments "$RUN_DIR/consolidate/judgments.json" --proposals-dir "$RUN_DIR/consolidate/proposals" --review-inputs "$RUN_DIR/consolidate/review-inputs.json" --out "$RUN_DIR/consolidate/settled.json"  # timeout: 30000
```

## Phase 5 — Independent review (`foundry:challenger`, always)

One challenger per `CONSOLIDATE_REVIEW_BATCH` entries of `review-inputs.json`, never a fork. Each entry carries only: its `digest` (a hash of exactly the change shown), the original sections' locations (file + line range), the citing files, and either the proposal file with its obligation map, survivor and `repoint` list (`kind: merge-prune`) or the edit list with its `repoint` list and `crosses_files` flag (`kind: sharpen`). Never the judge's reasoning: edits are copied with only `file`, `lines`, `action`, `before` and `after`. `review-inputs.json` empty → no review is spawned and the second settle below is skipped; `settled.json` already stands. Spawn `review-N`; prompt line 1 names the entry slice. Substitute `<RUN_DIR>`, `N` and the slice's cluster ids (the prompt also names `<RUN_DIR>/consolidate/review-inputs.json`, from which the reviewer takes only those entries); scan the built prompt for the placeholder names `<RUN_DIR>` and `<cluster ids>` only, as in Phase 3. Prompt:

> Adversarial review of instruction changes. Read-only: write only your findings file. Take the entries for clusters `<cluster ids>` from `<RUN_DIR>/consolidate/review-inputs.json`. For each, read the original sections at the given locations and the proposed text (merge proposal, or edit list), then try to prove the change loses something: an obligation, a trigger or incident condition, an exception, a threshold or literal, modal strength (`must`/`never`/`only`/`before`), an actor, an ordering, or a stop condition — or broadens scope so the rule fires where it should not — or leaves a citing file pointing at a deleted heading — or, for an entry with `crosses_files: true` (a skill or agent cluster), moves an obligation from one file into another under any wording — verdict `weakens`, quoting both places, because that is a merge and merging is not allowed there. Verdict per cluster: `holds` (nothing lost, with the check you ran), `weakens` (kept but softened or broadened — quote both), `loses` (an obligation is gone — quote it). Write `<RUN_DIR>/consolidate/review-N.json` as a list of `{"cluster":"<id>","digest":"<the entry's digest, copied unchanged>","verdict":"holds|weakens|loses","evidence":"<quotes>"}`. Return ONLY: `{"status":"done","file":"<path>","proposals":N,"holds":N,"weakens":N,"loses":N,"confidence":0.N}`

After the wave, merge the reviews and settle again with them:

```bash
export CSID="${CLAUDE_CODE_SESSION_ID:-$PPID}"
IFS= read -r RUN_DIR < "${TMPDIR:-/tmp}/audit-state-${CSID}/consolidate-run-dir" 2>/dev/null || RUN_DIR=""
[ -n "$RUN_DIR" ] || { echo "! BLOCKED — consolidate run-dir sentinel missing; re-run /foundry:audit --consolidate"; exit 1; }
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" collect --dir "$RUN_DIR/consolidate" --glob 'review-[0-9]*.json' --out "$RUN_DIR/consolidate/reviews.json"  # timeout: 10000 — no match (every challenger timed out) gives []; the entries stay unvalidated
python "${CLAUDE_PLUGIN_ROOT:-plugins/cc_foundry}/bin/consolidate_inventory.py" settle --inventory "$RUN_DIR/consolidate/inventory.json" --vetted "$RUN_DIR/consolidate/vetted.json" --judgments "$RUN_DIR/consolidate/judgments.json" --proposals-dir "$RUN_DIR/consolidate/proposals" --reviews "$RUN_DIR/consolidate/reviews.json" --review-inputs "$RUN_DIR/consolidate/review-inputs.json" --out "$RUN_DIR/consolidate/settled.json"  # timeout: 30000
```

A verdict applies only to the change whose `digest` it carries; one with another or no digest (a stale or reused review file) is ignored, noted in `downgrades`, and leaves the entry `unvalidated`. The verdicts apply mechanically: `holds` keeps the decision; `weakens` → `rejected` with the quoted difference (never relabelled `sharpen`); `loses` → `keep`. A challenger that is missing, timed out or unavailable leaves its entries `unvalidated`: reported as such and **not** presented as ready to apply.

## Phase 6 — Report

Write `<RUN_DIR>/consolidate/report.md` from `settled.json` starting with the YAML `---` metadata block (`Title`, `Date`, `Scope`, `Focus`, `Agents`, `Outcome`, `Confidence`, `Next steps`, `Path`, plus `Groups examined`, `Groups not examined`, `Clusters`, `Merge-prune`), then, in order:

1. **Summary** — `totals.savings` per load class: tokens before/after for validated proposals; always-loaded savings separate from per-invocation (lazy) savings; `unvalidated` amounts shown apart, never added to validated ones.
2. **Proposals** — per `merge-prune` cluster: id, validation (`holds`/`unvalidated`), locations merged, surviving location, tokens before→after, `proposals/<id>.md`, `proposals/<id>.obligations.json`.
3. **Sharpen / keep** — one line each with the reason (distinct decision surface, incident condition, differing trigger); a sharpen that removes text shows its validation (`holds`/`unvalidated`); `downgrades` shown for any merge that fell back to sharpen; `rejected` entries show the reviewer's quote.
