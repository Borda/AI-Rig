# Adversarial Convergence Loop

Use when independent review produces findings and authorized work fixes them: pre-commit review, review/remediation pairs, root-cause fixes, report revision. A review-only request never authorizes edits. Canonical procedure; other plugins ship generated byte-identical copies — installation never needs a sibling plugin.

## Scope and authority

Before first review, record objective, specification, reported symptom, allowed files, implementation author, acceptance checks, existing workflow/run. Preserve unrelated changes. Unknown failures need root-cause evidence before a fix. Parent owns edits, integration, gates, acceptance; reviewers return evidence, not permission.

Run at most **3** independent review rounds by default, including initial review `W_0`. A round = review, triage, any permitted local fixes; those fixes need a later independent review before closure. Last round cannot end with an unreviewed fix presented as clean. Plan this bounded sequence before dispatch. Not permission to expand a parallel wave or bypass a caller's stricter reviewer admission, provenance, approval, or retry rules.

Each reviewer gets: specification, symptom, exact current diff, relevant source and acceptance evidence, scope exclusions, requested checks. Never supply the implementation narrative or fork the implementing agent's conversation. Identify earlier findings by stable signature when asking for verification; retain original evidence without the implementer's justification. Supply source inline when the reviewer can't read files — paths alone aren't inspectable context. Record actual reviewer identity and coverage. Claimed independence or a ledger field is not proof of runtime provenance.

State-changing workflows: include producer, its next consumer, next ordinary user action in the review boundary, plus relevant unchanged callers. Ask whether the verified postcondition actually establishes the consumer's precondition, and whether all local checks could pass while the user's intended result fails. Prior design approval and tests asserting the selected operation are insufficient evidence of that end-to-end property. Request a concrete counterexample or outcome-based probe for material assumptions on identity, ownership, destination, lifetime, retry, resume. Record missing downstream context as a coverage gap; zero findings does not establish uninspected workflow safety.

No permitted independent route available: stop the independent loop, reason `independence-unavailable`. Accessible parent-owned source inspection may continue within authorization, but it's sequential review without independent coverage. Preserve rejected specialist evidence separately; never relabel it accepted, substitute parent tests for independent review, or launch another paid/rejected route without required approval or changed evidence.

Before retry or a different route, record the observed failure class and its evidence. Unknown receipt rejection is not evidence of transient transport failure. Retry only when the owning workflow's retry contract permits that class; otherwise diagnose, or use a genuinely different permitted route with its limitations disclosed.

## Review, triage, fix, verify

1. Freeze a complete scoped snapshot before dispatch: staged, unstaged, relevant untracked content, not only committed `HEAD`. Record revision, exact diff SHA-256, source coverage, excluded paths. Preserve each round's diff and returned report unchanged.
2. Join the independent review before editing. Assign stable finding signatures from affected location and failure mechanism, not incidental wording. Each finding names severity, evidence, affected files, whether it changes a contract. Reconcile duplicates with traceable evidence; never drop an earlier finding from the ledger.
3. Validate findings against specification and actual source. A false positive may be `rejected` only with explicit refutation evidence. A patch becomes `fixed-pending-verification`; still counts open until an independent reviewer verifies the fix on the new snapshot. Tests support that verification but can't replace it. Carry closed entries forward so regression can reopen the same signature. Never rename findings or lower severity to manufacture progress.
4. Calculate the score from findings still open at the independently reviewed snapshot, including `fixed-pending-verification`. Apply hard stops before the trend table. On the initial review there is no ratio; if findings remain and no hard stop applies, make only authorized local fixes and use the next round.
5. Fix each valid finding where it sits, smallest change that closes it: one predicate, call site, or local implementation. A finding is never permission to restructure its surroundings. Run the relevant regression checks, freeze the changed snapshot, obtain the next independent review only if no stop condition applies and a round remains.
6. Before acceptance, capture the current snapshot again. Must match the final independently reviewed snapshot. Later edits, formatter changes, target merges, or source updates invalidate a clean claim until reviewed. Complete the caller's ordinary gates, artifact validation, promotion, final output; a clean loop is not a merge decision or automatic commit authorization.

After every completed challenge-resolve round, after triage and finding validation but before any next fix, review, or stop, Codex Rig runs `python shared/adversarial_loop.py --ledger <run-directory>/loop-ledger.json --progress`. This preserves the full cumulative progress transcript on stderr while leaving the JSON summary on stdout unchanged. Consumers without that helper still render the same table from the validated round. Show that full table to the user after each round; do not show a partial or unreviewed row.

The progress table has exactly these columns:

| Iteration | Critical | High | Medium | Low | Nits | Weighted score |
| -- | -- | -- | -- | -- | -- | -- |

Each numeric cell is the literal `old + new` split: `old` counts currently open signatures whose signature was seen in any prior completed round, including signatures that were closed and later reopened, and `new` counts currently open signatures first seen in the current round. The first row therefore uses `0 + current` in every numeric column. Count only `open` and `fixed-pending-verification`; exclude `verified-fixed` and `rejected`. The `Critical` display combines `security` and `critical`, while the score retains weights security 20, critical 10, high 6, medium 4, low 2, and nit 1; `Weighted score` is `old weighted + new weighted`, and its sum equals the existing `W_n`. An empty ledger emits `not-run` with `N/A` cells instead of an unreviewed zero row.

The stderr transcript includes a legend explaining the old/new split and repeats the complete cumulative table on every invocation, preserving all prior rows. With no rounds, emit one `not-run` iteration whose cells are `N/A`; do not fabricate a zero row. This in-turn progress output is separate from the final result table.

### Table delivery checkpoint

Never omit the convergence table from a challenge status update, approval/recovery question, pause, or final handoff after the loop starts. Before sending an in-turn message, include the complete current progress table, not merely a score in prose or a link to the ledger. A stopped or resumed run retains this obligation. The canonical final Results table satisfies the final-handoff checkpoint; preserve its required columns rather than adding a second table or replacing it with the progress format.

- Validated rounds exist: repeat all completed rows from the checker. A pending fix or reviewer is not a new completed row.
- No validated round exists, including missing reviewer coverage, rejected provenance, or pending approval: show `not-run` with `N/A` in every numeric cell and explain the actual missing evidence. Do not suppress the table because the review is incomplete or report zero as if clean.
- Reviewer returns and parent triage may be described separately as provisional findings; never silently substitute their counts for validated convergence scores. After validation, run the checker and show its full cumulative table before the next fix, dispatch, question, or stop.

An instruction to keep the reply short does not waive this checkpoint. Only an explicit caller-required exact output format may supersede the displayed table; retain the table in the artifact and state the exception when that caller format permits.

## Scores and stop rules

Sum weights of open findings once per stable signature:

| security | critical | high | medium | low | nit |
| -- | -- | -- | -- | -- | -- |
| 20 | 10 | 6 | 4 | 2 | 1 |

`W_n` = score at independent review *n*, initial `W_0`. `r_n = W_n / W_{n−1}`; never divide when the previous score is zero — that run is already clean. Severity follows demonstrated impact. Explain disputed assignments; never inflate stylistic issues or soften security defects for a better score.

Hard stops override score improvement:

- An open or `fixed-pending-verification` structural finding stops the loop immediately; apply no further changes. Structural = changing a contract: script arguments/output, module boundary, shared schema, skill step order, or any fix reaching files the finding doesn't name. Report its blast radius, ask explicit approval as a separately scoped change; never silently apply it inside the loop, even as the only finding or at `r_n ≤ 0.5`. A separately approved correction run may retain independently `verified-fixed` structural findings as closed evidence; they score zero, don't block that run. Preserve the original stopped ledger; appending a later closure to it never authorizes continuation.
- Same open finding signature in two consecutive reviews stops immediately; don't wait for the cap.
- Any open `security` or `critical` finding forbids declaring done or committing, whatever the trend; may still get an authorized local fix when no other stop applies.
- Missing independent coverage, invalid evidence, or a stale final snapshot cannot produce a clean decision.

| Condition | Reading | Action |
| -- | -- | -- |
| `W_n == 0` and current independent coverage is valid | clean | Complete the owning workflow's remaining gates. |
| `r_n ≤ 0.5` | converging | Continue only if rounds remain and no hard stop applies. |
| `0.5 < r_n < 1.0` | plateau | Stop this approach; ask for the next scoped decision. |
| `r_n ≥ 1.0` | non-converging | Stop immediately; another unchanged attempt is not justified. |
| Round limit reached with findings open | round-cap | Stop; disclose remaining findings and request direction. |

Stopping on a plateau is a valid process outcome — not successful remediation, not proof the task is permanently impossible. Preserve the score series and stopped ledger. Further work needs the specific missing decision or materially changed scope/evidence; a new invocation alone never resets recurrence or bypasses a stop.

## Evidence ledger

Keep `loop-ledger.json` and `loop-report.md` in the owning run. Ledger records observed facts; a checker establishes structural consistency, not reviewer authenticity or source correctness.

Schema version `1` uses these fields:

- Root: `schema_version`, `implementation_author`, `current_snapshot`, `rounds`.
- Snapshot: nonempty `revision`, lowercase 64-hex `diff_digest` of exact retained snapshot bytes.
- Round: one-based `index` (1–3; score labels start at `W_0`), `reviewer`, `snapshot`, `report_path`, `findings`.
- Reviewer: nonempty `identity`, boolean `independent`. Identity differs from the implementation author; record effective host provenance in the report, including unavailable verification. Empty rounds list records unavailable independent review, never a clean review.
- Finding: stable `signature`, `tier`, boolean `structural`, `disposition`, list of nonempty `evidence` strings. Dispositions: `open`, `fixed-pending-verification`, `verified-fixed`, `rejected`; last two require closure/refutation evidence. Carry every prior signature, tier, structural classification into later rounds. Reopened findings retain their signature.

Each report includes inspected snapshot and coverage, reviewer route/provenance limits, original findings, refutations, verification evidence, any missing inputs. Retain `round-<index>.diff` and `current.diff` for digest checks; report paths resolve inside the run. Unchanged snapshot digest does not prove independence. Changed snapshot invalidates prior closure evidence relevant to that change.

## Handoff and recovery

Start with topic and outcome — e.g. “The parser review stopped because the same boundary defect remained in two independent rounds.” Never open with an unexplained “both,” “that,” “blocked,” or internal error code. State each fact once; don't repeat the entire conversation.

For every stop with open findings, report score series (`W_0 → W_1 → W_2`), per-tier counts, each remaining finding's disposition and reason, evidence, owner, next action. Distinguish code changes from evidence-only closure and target integration. Passing gates doesn't close findings; zero implemented fixes must be explicit.

Show only completed-round scores: first-round stop = `W_0`, second-round stop = `W_0 → W_1`. Three-label series is an example, not a requirement to invent rounds. No independent round: show `not-run` and the unavailable reason; never assign zero — implies a clean review.

Explain why the loop stopped in plain English, what can safely continue. Recommend one concrete recovery, name meaningful alternatives. Ask only for the missing decision or authority; never ask the user to repeat approval already given. After an authorized recovery, resume the first unmet checkpoint of the original workflow, finish its normal closing checks. Don't stop merely to tell the user to rerun a command the agent can already execute safely.
